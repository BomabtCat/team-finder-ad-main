# TeamFinder

TeamFinder — Django-приложение для поиска участников в pet-проекты. Пользователи могут регистрироваться, публиковать проекты, откликаться на чужие проекты, редактировать профиль и управлять своими проектами.

Реализован **вариант 3**: необходимые навыки проектов и фильтрация проектов по навыкам.

## Что реализовано

- Регистрация и вход по email/password.
- Выход из аккаунта.
- Публичные профили пользователей.
- Редактирование профиля, аватара и контактов.
- Смена пароля.
- Список пользователей с пагинацией по 12 профилей.
- Список проектов с пагинацией по 12 карточек.
- Создание, редактирование и завершение своих проектов.
- Участие в чужих проектах и отказ от участия.
- Страница проекта с участниками и блоком «Необходимые навыки».
- Добавление и удаление навыков проекта без перезагрузки страницы.
- Автодополнение навыков через `/projects/skills/?q=...`.
- Фильтрация проектов по навыку через `?skill=<Название>`.
- Админ-панель Django для управления пользователями и проектами.

## Стек

- Python
- Django 5.2
- PostgreSQL
- Docker Compose
- Pillow
- python-decouple

## Вариант задания

В `.env` должен быть указан третий вариант:

```env
TASK_VERSION=3
```

При таком значении Django использует шаблоны из папки `templates_var3`.

## Быстрый запуск

Создайте и активируйте виртуальное окружение:

```bash
python3 -m venv venv
source venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Создайте `.env` из примера:

```bash
cp .env_example .env
```

Заполните `.env`. Для локального запуска с текущим `docker-compose.yml` можно использовать такие параметры:

```env
DJANGO_SECRET_KEY=your_secret_key
DJANGO_DEBUG=True

POSTGRES_DB=team_finder
POSTGRES_USER=team_finder
POSTGRES_PASSWORD=team_finder
POSTGRES_HOST=localhost
POSTGRES_PORT=5436

TASK_VERSION=3
```

Запустите PostgreSQL:

```bash
docker compose up -d
```

Примените миграции:

```bash
python manage.py migrate
```

Запустите сервер разработки:

```bash
python manage.py runserver 8001
```

Откройте:

```text
http://127.0.0.1:8001/projects/list
```

Корневой адрес `/` перенаправляет на список проектов.

## Основные URL

- `/` — редирект на список проектов.
- `/projects/list` — список проектов.
- `/project/list/` — совместимый адрес списка проектов из задания.
- `/projects/<id>/` — страница проекта.
- `/projects/create-project/` — создание проекта.
- `/projects/<id>/edit/` — редактирование проекта.
- `/projects/skills/?q=<query>` — автодополнение навыков проектов.
- `/users/register/` — регистрация.
- `/users/login/` — вход.
- `/users/logout/` — выход.
- `/users/list/` — список пользователей.
- `/users/<id>/` — профиль пользователя.
- `/users/edit-profile/` — редактирование профиля.
- `/users/change-password/` — смена пароля.
- `/admin/` — админ-панель.

## Проверка варианта 3

На странице проекта владелец видит кнопку добавления навыка. При вводе названия отправляется запрос:

```text
GET /projects/skills/?q=Dja
```

Добавление навыка:

```text
POST /projects/<id>/skills/add/
```

Удаление навыка:

```text
POST /projects/<id>/skills/<skill_id>/remove/
```

Фильтрация проектов по навыку:

```text
/projects/list?skill=Django
/project/list/?skill=Django
```

## Администратор

Создать администратора можно командой:

```bash
python manage.py createsuperuser
```

После этого админ-панель будет доступна по адресу:

```text
http://127.0.0.1:8001/admin/
```

## Примечания для ревьюера

- Реализован только вариант 3.
- Для совместимости работают оба адреса списка проектов: `/projects/list` и `/project/list/`.
- PostgreSQL в Docker проброшен на порт `5436`, чтобы не конфликтовать с локальным PostgreSQL на стандартном порту `5432`.

## Исправления после ревью

- Повторяющаяся пагинация вынесена в общую функцию `paginate_queryset`.
- Числовые значения, которые использовались в моделях, формах и генерации аватара, вынесены в константы.
- Проверка GitHub-ссылок, разбор JSON-запросов, нормализация телефона и генерация аватара вынесены в `utils.py`.
- В JSON-ответах вместо числовых HTTP-кодов используется `HTTPStatus`.
- Удалены пустые `tests.py` и стандартные комментарии-заглушки Django.
- В проектной реализации оставлены шаблоны и логика для варианта 3.
